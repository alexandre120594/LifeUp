Productivity Design System

Calmo, denso e funcional.

Uma linguagem de interface para um app de produtividade com hierarquia limpa, baixa distração, superfícies discretas e componentes previsíveis. Inspirado no vocabulário visual do SnowUI, mas adaptado para metas, foco, tarefas, sequência e planejamento.

Regras para o Codex implementar

Use este contrato junto do HTML. O objetivo é manter arquitetura visual consistente quando os componentes forem migrados para o app real.
✓ Tokens primeiro

Crie CSS variables ou theme tokens e faça todos os componentes consumirem nomes semânticos: background, foreground, border, primary, success, danger.

✓ Componentes pequenos

Button, Input, Badge, Progress, Card, NavItem, TaskRow e GoalCard devem existir como peças independentes antes do Dashboard.

✓ Full-screen app shell

O shell usa 100dvh. Sidebar e topbar ficam fixos dentro do layout; só a região de conteúdo recebe overflow:auto.

✓ Estados completos

Preserve hover, pressed, focus-visible, disabled, loading e selected. Não dependa apenas de cor para comunicar estado.

× Não usar cores aleatórias

Novas categorias devem reutilizar a paleta. Cores novas só entram como token documentado e com uso semântico claro.

× Não criar card dentro de card sem motivo

Prefira grupos com borda simples e espaçamento. Evite excesso de contêineres, sombras e painéis aninhados.
